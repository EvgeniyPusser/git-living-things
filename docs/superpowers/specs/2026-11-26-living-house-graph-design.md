# Помощник «Живой дом» — топологический граф

Дата: 2026-11-26. Статус: черновик на согласование.

## Зачем

Портал Living Things (portal.living-things.org) принимает паспорта объектов от приглашённых учёных, институтов и инвесторов. Когда клиент описывает **дом**, ему нужен помощник, который:

- проведёт его **по шагам** от обычного дома к **живому**: дом сам поддерживает гомеостаз и сам себя ремонтирует, постоянно и разово;
- покажет, **хватает ли** дому компонентов живости и где разрывы;
- подходит **любому** дому с фундаментом, стенами и крышей. Поэтому в нём нет размеров и форм, только граф частей и связей.

Помощник **необязателен**: клиент может им пользоваться, а может и нет.

## Цели

1. Клиент собирает граф дома: тело, нервы, центры, сети, запасы, механизмы реакции и заживления, Конституцию.
2. Для каждого конструктивного элемента помощник проверяет два круга: постоянное поддержание и разовый ремонт. Результат — карта: зелёный, жёлтый или красный элемент, с пояснением, чего не хватает.
3. По желанию узлы графа привязываются к элементам загруженного проекта клиента (IFC, DWG, DXF).
4. Модель сохраняется в паспорт на портале и открывается из него.
5. По графу помощник **предлагает варианты текста** для разделов паспорта. Клиент вставляет вариант, правит его или пишет свой. Свой текст никогда не затирается.

## Не цели (сейчас)

- Сценарии, катастрофы и испытания. Они будут позже, на этом же графе, и **платными**.
- Геометрия, размеры, расчёт конструкций.
- Автоматическое чтение IFC и построение графа из проекта. Это будет позже, сейчас привязка ручная.

## Анти-цели

- Сказка вместо описания. Тело описываем только словарём из признанных стандартов, а не придуманными терминами.
- Привязка к одному типовому дому. Если граф годится только для образцового коттеджа, задача провалена.
- Обязательность. Помощник не должен мешать подать паспорт без него.

## Ограничения

- Вся работа идёт в репозитории портала `git-living-things`, в папке `house-model/`. Это статичная страница без сборки, она публикуется вместе с порталом на portal.living-things.org. Отдельный репозиторий `living-house-model` больше не используется для встраивания. Коммиты делает автор сам.
- Встраивание остаётся окном в паспорте с обменом сообщениями `postMessage` (протокол из `living-house-model/PORTAL.md`). Программа теперь живёт на том же адресе, что и портал, поэтому `houseApp` в `app.js` становится `location.origin`, а адрес окна — `house-model/`. Портал проверяет `format === "living-house-model"`. Значение не меняем, меняем `version` на `"1.0"` и структуру.
- Сохраняет только владелец паспорта. Файл `*.living-house.json` прикладывается к паспорту, не больше 5 МБ.
- Интерфейс на английском и русском, светлая и тёмная тема, как сейчас.

## Подходы

| Подход | Плюсы | Минусы |
|---|---|---|
| **1. Отдельная программа (`git-living-things/house-model/`), встроенная в паспорт** (выбран) | связь с порталом уже работает; платные тесты легко отделить позже | клиент работает в окне внутри паспорта |
| 2. Граф прямо в форме паспорта на портале | всё в одном месте | разрастается код портала; трудно отделить платные тесты |
| 3. Граф таблицами, без рисунка | дёшево | клиент не видит дом и разрывы кругов |

Выбран подход 1. Нынешняя геометрическая программа (контуры в метрах, этажи с высотами, образец-коттедж, симуляция) **заменяется**. Из неё переиспользуется Конституция (приоритеты, пределы, запреты, принципы), переключение языка и темы.

## Модель

### Откуда словарь

- **Тело**: классы IFC (ISO 16739) и топология W3C BOT. Это делает граф совместимым с проектом клиента.
- **Нервы и управление**: по смыслу Brick Schema (кто что измеряет, что чем управляет, что куда подаёт).
- **Живость**: концепция Living Things из проектов автора: `living-building-assembly` (чипы в элементах, контроллеры в центрах, пять сетей и ремонтная сеть, датчики целостности, подвижные датчики, реакция на повреждение и ремонт из центра), `living-building-morphogenesis-v2` (ДНК, Конституция, центры, строительный и управляющий материал, предиктор и датчик, регенерация), `structural-regeneration` (заживление больших трещин, компенсация, доноры).

### Узлы

| Слой | Типы узлов |
|---|---|
| Тело: пространство | участок, здание, этаж, помещение |
| Тело: элементы (конструктивные) | фундамент, стена, колонна, балка, перекрытие, крыша |
| Тело: прочие элементы | окно, дверь, лестница |
| Нервы | датчик (конструктивный: деформация, трещина, нагрузка, наклон; целостности; среды: температура, влажность, CO₂, протечка); подвижный датчик; чип элемента; линия связи |
| Мозг | центр (морфогенетический: контроллер, роботы, запасы); ДНК (допустимые диапазоны реакций, например «усиление соседа до +20 %»); Конституция |
| Сети | вода, электричество, газ, воздух, ремонтный материал, данные |
| Запасы | строительный материал, управляющий материал |
| Исполнители | адаптивный материал (свойство: теплопроводность, прозрачность, отражение, залечивание трещин, заделка протечек); устройство (отопление, вентиляция…); временная мера (подпорка, закрытая зона, усиление соседа); робот |

У каждого узла есть `id`, тип, название и необязательная **привязка**: файл проекта из вложений паспорта и обозначение элемента в нём (GUID IFC, номер листа или марка).

### Связи

| Связь | Откуда → куда |
|---|---|
| опирается на | элемент → элемент |
| примыкает | элемент ↔ элемент |
| содержит | пространство → пространство или элемент |
| наблюдает | датчик → элемент или помещение |
| обходит | подвижный датчик → элементы |
| передаёт | датчик → чип → … → центр (по линиям связи) |
| управляет | центр → исполнитель |
| действует на | исполнитель → элемент или помещение |
| обслуживает | сеть → элемент или помещение |
| питает | запас → сеть; центр → сеть |
| залечивает | адаптивный материал с залечиванием → элемент |

## Шаги помощника

1. **Тело.** Фундамент, стены, перекрытия, крыша, помещения, связи «опирается» и «примыкает». Стартовый каркас: фундамент → стены → перекрытие → крыша. Клиент добавляет и удаляет узлы.
2. **Нервы.** Датчики на элементах, подвижные датчики, чипы, линии связи.
3. **Центры и мозг.** Центры, ДНК (диапазоны реакций), Конституция.
4. **Сети и запасы.** Какие сети к каким элементам идут, откуда питаются.
5. **Реакция и заживление.** Адаптивные материалы, устройства, временные меры, роботы.
6. **Привязка к проекту** (необязательно). Узел ↔ элемент проекта клиента.
7. **Оценка.** Карта живости и список разрывов.

Шаги можно проходить в любом порядке и пропускать. Оценка видна всё время.

## Оценка живости

Для каждого **конструктивного** элемента E:

**Постоянное поддержание** замкнуто, если выполнены все условия:
- (а) есть датчик, который наблюдает E или его помещение;
- (б) от датчика есть путь «передаёт» до центра C;
- (в) в Конституции есть норма для этого вида измерения;
- (г) C управляет исполнителем, который действует на E или его помещение;
- (д) на E есть непрерывное залечивание (адаптивный материал со свойством залечивания).

**Разовый ремонт** замкнут, если выполнены все условия:
- (а) E наблюдается датчиком целостности или конструктивным датчиком, либо входит в обход подвижного датчика;
- (б) от датчика есть путь до центра C;
- (в) есть временная мера для E: подпорка, закрытая зона или усиление соседа, разрешённое ДНК;
- (г) E обслуживается ремонтной сетью, которая питается от запаса строительного материала;
- (д) у центра C есть робот или иной исполнитель ремонта.

**Цвет элемента:**
- зелёный — оба круга замкнуты;
- жёлтый — замкнут один круг или выполнена часть условий;
- красный — нет ни одного датчика: дом элемент не чувствует.

У каждого невыполненного условия есть понятная подсказка, например: «Стена S-2: датчик есть, но не связан с центром».

Оценка подсказывает, а не запрещает. Сохранять можно граф в любом состоянии.

## Варианты текста для паспорта

Модуль `house-model/suggest.js` по графу строит черновые тексты для разделов паспорта. Он общий: им пользуются и помощник, и форма редактирования паспорта. Разделы и что в них попадает:

| Раздел паспорта (`taxonomy.js`) | Из графа |
|---|---|
| Каркас, оболочка… (`structureProject`) | конструктивные элементы и связи «опирается» |
| Энергоснабжение, сети и ресурсы (`supplyProject`) | сети, что обслуживают, откуда питаются; запасы |
| Минимальный набор датчиков (`minimumSensors`) | датчики: вид, на чём, подвижные и их обход |
| Нервная система и журнал (`nervousSystem`) | чипы, линии связи, к каким центрам |
| Система поддержания гомеостаза (`homeostasisControl`) | постоянные круги: датчик → центр → норма → исполнитель |
| Конституция объекта (`constitution`) | приоритеты и правила Конституции |
| Реакция на повреждение и разрушение (`damageScenarios`) | временные меры, ДНК-диапазоны |
| Система самовосстановления (`selfRecovery`) | залечивание, ремонтная сеть, роботы, запас материала |

Тексты сухие и перечислительные, с обозначениями узлов («Колонны C-1…C-4: датчик деформации, передаёт в центр C1»), на языке интерфейса. Разрывы из оценки тоже попадают в текст как «не предусмотрено: …», чтобы клиент видел их в паспорте.

**В форме паспорта:** если к паспорту приложена модель дома, под каждым из этих полей появляется свёрнутый блок «Вариант из модели дома» с кнопками «Вставить» (в пустое поле), «Добавить в конец» и «Скрыть». Поле остаётся обычным: клиент может ничего не вставлять. Портал ничего не подставляет сам.

**В помощнике:** на шаге «Оценка» те же варианты видны списком, чтобы клиент понимал, что получит в паспорте.

## Вид

Узлы раскладываются автоматически по ярусам. Снизу фундамент, выше стены и перекрытия, сверху крыша. Слой нервов, центров и сетей справа. Клиент не рисует, а добавляет узлы и связи через панели, и может сдвигать узлы. Цвет конструктивного элемента показывает оценку.

## Портал
