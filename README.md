# Living Things

Двуязычный научно-технический портал для описания технических систем и компонентов по их свойствам Living Things.

## Запуск

Требуется Node.js 24 или новее. Установка пакетов не нужна.

```sh
npm start
```

Откройте http://127.0.0.1:4173. Чистая база создаётся автоматически в `var/portal.sqlite`. Сервер обслуживает интерфейс и API с одного адреса. Все клиенты этого сервера работают с одной базой в SQLite.

Тесты: `npm test`.

## Помощник «Живой дом»

Необязательный помощник для паспортов домов, папка `house-model/`. Клиент собирает дом как граф частей и связей без размеров: тело (по IFC и BOT), датчики и нервы, центры, ДНК и Конституцию, сети и запасы, исполнители и заживление. Для каждого несущего элемента помощник проверяет два круга — постоянное поддержание и разовый ремонт — и показывает, чего не хватает.

- В паспорте с областью «Здания» панель «Модель живого дома» открывает помощник во фрейме. Сохраняет только владелец: модель прикладывается к паспорту файлом `*.living-house.json`. Остальные видят её только для чтения.
- В форме паспорта под разделами проекта дома появляется «Вариант из модели дома». Клиент вставляет его, дописывает или пишет своё. «Вставить» не заменяет уже написанный текст.
- Отдельно помощник открывается по адресу `/house-model/` и сохраняет модель файлом на компьютер.
- Формат файла: `house-model/FORMAT.md`. Логика без интерфейса (`graph.js`, `check.js`, `suggest.js`) покрыта тестами.

## Хранение и доступ

- Регистрация создаёт аккаунт в базе. Пароли хранятся в виде хешей scrypt, сессии используют HttpOnly cookie.
- Черновики и закрытые паспорта доступны владельцу аккаунта. Опубликованный паспорт с публичным доступом доступен всем посетителям. Изменения и загрузка вложений доступны владельцу, комментарии могут оставлять вошедшие пользователи с доступом к паспорту.
- Права проверяются сервером и распространяются на каталог, сравнение, связанные объекты, вложения и историю версий. В публичной истории видны версии, сохранённые с публичным доступом и статусом публикации.
- Вложения хранятся в той же базе. Допускается до 50 МиБ на файл и до 250 МиБ на паспорт. При загрузке можно указать тип файла и ревизию. Модели DWG, DXF и IFC доступны для скачивания, а фотографии PNG, JPEG и WebP можно показать в паспорте. Внешние ссылки должны использовать HTTP или HTTPS.
- Справочники областей, типов, уровней, стадий и отношений находятся в `taxonomy.js`. Для новой области добавьте название, описание, поля и, при необходимости, ссылки на инструменты.

## Развёртывание

Для общего доступа нужен хост с Node.js 24+, HTTPS и постоянным диском. Запустите один экземпляр приложения за HTTPS-прокси. Параметры процесса:

| Переменная | Назначение |
| --- | --- |
| `HOST` | Адрес прослушивания, по умолчанию `127.0.0.1` |
| `PORT` | Порт приложения, по умолчанию `4173` |
| `LIVING_THINGS_ORIGIN` | Внешний HTTPS-адрес без завершающей косой черты, например `https://portal.example.org`. Включает Secure для cookie и используется при проверке источника запросов на запись. |
| `LIVING_THINGS_DB` | Путь к файлу SQLite на постоянном диске |
| `LIVING_THINGS_TRUST_PROXY` | `1`, если приложение работает за HTTPS-прокси. Тогда ограничение попыток входа считается по адресу клиента из последней записи `X-Forwarded-For`, а не по адресу прокси. Без прокси не включайте: заголовок может подделать сам клиент. |

Настройте резервное копирование через механизм снимков SQLite или копируйте базу после остановки процесса.

### Публичный сайт на GitHub Pages

Версия на `https://portal.living-things.org/` (адрес `https://evgeniypusser.github.io/git-living-things/` перенаправляет туда) использует Supabase Auth, Data API и приватный бакет вложений. Локальный сервер использует SQLite. Публичный клиент Supabase подключён в `supabase-backend.js`.

1. В проекте Supabase включите Data API. Миграция в `supabase/migrations/` создаёт таблицы и хранилище с правилами доступа. Если включён **Deploy to production** для `main`, GitHub-интеграция применит миграцию при отправке ветки.
2. В **Authentication → URL Configuration** установите **Site URL** на `https://portal.living-things.org/`. В разрешённые редиректы добавьте `https://portal.living-things.org/**` и `https://evgeniypusser.github.io/git-living-things/**` для возврата после подтверждения email.
3. Настройте SMTP Supabase для писем подтверждения внешним пользователям. Проверьте форму регистрации и загрузку файла с отдельного тестового аккаунта на публичном сайте.

Хранилища SQLite и Supabase создаются отдельно. Для переноса существующих локальных аккаунтов и паспортов потребуется отдельный импорт.

Локальные аккаунты создаются сразу. Старые страницы прототипа хранятся в репозитории. Новый портал не импортирует их демонстрационные записи.

Ссылки на программы и статьи находятся в соответствующих предметных разделах. Материалы соседних проектов доступны при открытии портала на `localhost` или `127.0.0.1`. Чтобы открыть локальные версии рукописей о концепции Living Things и морфогенезе, укажите путь к папке архива `ARTICLE` в переменной `LIVING_THINGS_ARTICLE_DIR` при запуске сервера.

В каждом предметном разделе ссылка «Посмотреть пример» показывает путь от паспорта и источника данных до процедуры и результата. Там можно скачать шаблон CSV. При создании своего объекта из примера портал заполняет только предметную область, тип и уровень.
